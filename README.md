# AI Security Workflow (CyberFlow)

Визуальный конструктор сценариев проверки безопасности для учебных Kotlin/Spring Boot проектов.

- `backend/`: FastAPI принимает графы, воркер выполняет задания из PostgreSQL, а анализаторы Secrets, SCA и SAST формируют находки и отчёты. [Запуск, Swagger и проверка бэкенда](backend/README.md)
- `frontend/`: редактор сценариев на React, Vite и React Flow. [Запуск фронтенда](frontend/README.md)
- [AI-отчёты и подключение MCP-ассистента](backend/MCP.md)

[Локальная приёмка, отчёты и сценарий защиты](docs/demo/README.md)

## Деплой через Docker Compose

На сервере с Git, Docker Engine и плагином Docker Compose скачайте ветку и положите подготовленный `.env` рядом с `compose.yaml`. Если создаёте конфигурацию впервые, скопируйте [шаблон для деплоя](deploy/env.example) в `.env` и заполните его.

```bash
git clone --branch codex/agent-workflow-docs https://github.com/ReiBestFun/Cybergarden2026_cin.git cyberflow
cd cyberflow
# Поместите сюда .env
docker compose up -d --build
```

Для публичного сервера укажите в `APP_BASE_URL` свой HTTPS-адрес, направьте DNS домена на сервер и откройте входящие TCP-порты 80 и 443. Caddy выдаёт сертификат, отдаёт фронтенд и проксирует API на том же домене. Для проверки на своей машине подойдёт `APP_BASE_URL=http://localhost`.

Для входа укажите `GITHUB_CLIENT_ID` и `GITHUB_CLIENT_SECRET` из GitHub OAuth App. В настройках приложения задайте **Homepage URL** равным `APP_BASE_URL`, а **Authorization callback URL** — `<APP_BASE_URL>/api/auth/github/callback`. Для новой базы задайте пароль PostgreSQL и сгенерируйте два независимых ключа шифрования командами из шаблона.

После запуска откройте сайт и нажмите «Войти через GitHub». По адресу `/api/health` должен появиться ответ `{"status":"ok","db":"ok"}`. Команда `docker compose ps -a` показывает состояние сервисов. Контейнер `migrate` завершается с кодом 0 до запуска API и воркеров.

| Возможность | Настройка |
| --- | --- |
| Локальный AI | В шаблоне включён профиль `ollama`. При первой загрузке нужен интернет и место на диске для модели. Ход загрузки виден через `docker compose logs -f ollama-model`. |
| Внешний AI | Уберите `ollama` из `COMPOSE_PROFILES` и подключите провайдера и модель в настройках командного пространства. |
| Привязка Telegram | Заполните `TELEGRAM_BOT_TOKEN` и добавьте профиль `telegram`. Для одного бота запускайте один обработчик привязки. |
| Почта | Задайте параметры `SMTP_*` и список `NOTIFY_EMAIL_RECIPIENTS`. |
| Аудит | PostgreSQL хранит журнал. В настройках пространства можно выбрать дополнительный архив `docker-archive` на постоянном томе. |

Для обновления сохраните резервную копию базы и обоих ключей шифрования, затем в той же директории выполните `git pull --ff-only` и `docker compose up -d --build`. PostgreSQL, архив журналов, сертификаты и скачанные модели хранятся в именованных томах. Для переноса существующей установки на другой сервер вместе с `.env` восстановите данные из резервной копии.

## Работа с агентами в Codex

1. Обновите локальную копию репозитория и откройте её корень как проект в Codex. Проектные навыки уже лежат в [`.agents/skills/`](.agents/skills), а инструкции и ссылки для агента — в [`AGENTS.md`](AGENTS.md). Отдельно устанавливать навыки не нужно.
2. Начните новый чат в этом проекте. Наберите `$` и выберите навык из списка. В Codex CLI также можно открыть список командой `/skills`. Если после обновления навык не появился, перезапустите Codex и проверьте, что открыт корень репозитория.
3. Для работы с GitHub Issues установите GitHub CLI, сделайте его доступным в `PATH` и войдите в аккаунт с доступом к проекту. Достаточно проверить команды `gh auth status` и `gh issue list --repo ReiBestFun/Cybergarden2026_cin`. [Установка GitHub CLI](https://cli.github.com/)

| Навык в Codex | Когда использовать |
|---|---|
| `$grill-with-docs` | Разобрать спорные требования и согласовать решения. |
| `$to-spec` | Собрать согласованные решения в спецификацию. |
| `$to-tickets` | Разбить спецификацию на GitHub Issues с критериями и блокерами. |
| `$implement` | Реализовать конкретную задачу. Укажите её номер или ссылку. |
| `$code-review` | Проверить изменения относительно заданной ветки или коммита. |

Пример запроса в Codex:

```text
$implement Выполни https://github.com/ReiBestFun/Cybergarden2026_cin/issues/7
```

Для новой работы выберите открытую задачу без незакрытых блокеров. Перед реализацией прочитайте её критерии приёмки. Если клиент поддерживает команды вида `/implement`, используйте команду этого клиента. В Codex выбирайте проектный навык через `$`.
