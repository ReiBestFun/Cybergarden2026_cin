# Domain docs

## Before exploring

- Read the root `GLOSSARY.md`.
- Read the ADRs in `docs/adr/` that cover the area you are about to work in. If that directory is absent, continue. Use `/domain-modeling` to record terms and decisions as they are resolved.

## When writing

- Use glossary terms in issue titles, proposals, hypotheses, and test names. Bring gaps in the vocabulary to `/domain-modeling`.
- If a proposal conflicts with an ADR, cite the ADR and explain why the decision should be revisited.
