# AI в CyberFlow

## Сценарий по тексту

В редакторе откройте «Создать по описанию». Например, попросите ежедневно в 14:00 проверять учебный репозиторий на секреты и отправлять отчёт по почте. Модель выбирает тип запуска, анализаторы и параметры. Бэкенд строит граф и проверяет его тем же валидатором, что и воркер.

Редактор открывает черновик и указывает, какие параметры нужно заполнить. Если в описании нет часового пояса, используется часовой пояс профиля. При недостающих параметрах расписание остаётся выключенным до настройки. Сохранение и запуск выполняются через обычные кнопки редактора. Модель задаётся настройками LLM бэкенда, перечисленными ниже.

## Фоновый отчёт

В редакторе соедините «Объединение находок» → «AI-отчёт» → Telegram или «Почта». Получатели задаются в ноде уведомления. Воркер сам вызывает модель после сканирования, сохраняет пояснение в истории запуска и передаёт его в текст уведомления. Полный текст доступен на странице результатов и в экспорте Markdown. Состав JSON с находками и решение порога CI определяют сканеры. При ошибке модели нода показывает причину, а уведомление передаёт исходную сводку.

В окружение воркера установите `python -m pip install -r backend/requirements.txt` из корня проекта. Параметры читаются из окружения или корневого `.env` при старте воркера.

| Параметр | Локальная Ollama (по умолчанию) | Внешний API или vLLM |
| --- | --- | --- |
| `LLM_PROVIDER` | `ollama` | `openai_compatible` |
| `LLM_BASE_URL` | `http://127.0.0.1:11434` | Базовый URL провайдера, обычно с `/v1` |
| `LLM_MODEL` | `qwen3.5:4b` | Имя модели у провайдера |
| `LLM_API_KEY` | Пусто | Серверный ключ, если требуется |

Ollama получает запрос к `/api/chat` с JSON-схемой. Совместимый провайдер должен поддерживать `/chat/completions` и `response_format=json_object`. Для удалённого адреса требуется HTTPS. Если воркер запущен в контейнере, loopback указывает внутрь этого контейнера.

В запрос к модели попадают тип правила, название, критичность и число совпадений для каждой из первых шести групп по критичности. Воркер сверяет ответ со схемой и номерами групп, отклоняет распознанные ссылки в тексте модели и подставляет пример файла, строку и advisory из находки. При большем числе групп отчёт отмечает остаток. Формальная проверка ссылок оставляет оценку качества самих советов за разработчиком.

## Инструменты MCP

MCP-клиент ассистента запускает `backend.app.mcp_server` как дочерний процесс и общается с ним по stdio. Модель ассистента выбирается в клиенте независимо от модели фоновых отчётов. Клиент может обращаться к локальной модели или к внешней с поддержкой инструментов. При облачном инференсе клиент может передавать провайдеру возвращённые пути, названия правил и текст отчёта.

| Инструмент | Что получает ассистент |
| --- | --- |
| `node_catalog` | Типы нод, порты, схемы конфигурации из каталога бэкенда |
| `check_workflow` | Результат проверки чернового графа валидатором воркера |
| `run_summary` | Статус запуска, покрытие, счётчики и сохранённые AI-рекомендации |
| `run_findings` | Страница находок с ID, правилом и местом в коде, до 50 записей за вызов |

Промпт `review_run` помогает разобрать результаты и отметить находки для ручной проверки. `draft_workflow` помогает составить по описанию JSON графа и проверить его до переноса в редактор. Сохранение и запуск сценария остаются за пользователем.

Установите `python -m pip install -r backend/requirements-mcp.txt` в окружение MCP-сервера. Пример для клиента с форматом `mcpServers` приведён ниже. Замените путь к проекту и UUID запуска из страницы результатов. Каталог и проверка графов доступны и без UUID, в том числе при остановленном API.

```json
{
  "mcpServers": {
    "cyberflow": {
      "command": "C:/projects/Cybergarden2026_cin/.venv/Scripts/python.exe",
      "args": ["-m", "backend.app.mcp_server"],
      "env": {
        "PYTHONPATH": "C:/projects/Cybergarden2026_cin",
        "PYTHONUTF8": "1",
        "CYBERFLOW_API_URL": "http://127.0.0.1:8000/api",
        "CYBERFLOW_MCP_RUN_ID": "00000000-0000-0000-0000-000000000001"
      }
    }
  }
}
```

Для чтения запусков задайте действующее значение cookie `cyberflow_session` в переменной `CYBERFLOW_MCP_SESSION_TOKEN` в личной конфигурации MCP-клиента. API проверяет владельца выбранного запуска. По истечении сессии обновите значение. Каталог и проверка графов работают без сессии.
