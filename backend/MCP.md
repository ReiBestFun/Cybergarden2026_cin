# AI в CyberFlow

## Сценарий по тексту

В редакторе откройте «Создать по описанию». Например, попросите ежедневно в 14:00 проверять учебный репозиторий на секреты и отправлять отчёт по почте. Модель выбирает тип запуска, анализаторы и параметры. Бэкенд строит граф и проверяет его тем же валидатором, что и воркер.

Редактор открывает черновик и указывает, какие параметры нужно заполнить. Если в описании нет часового пояса, используется часовой пояс профиля. При недостающих параметрах расписание остаётся выключенным до настройки. Сохранение и запуск выполняются через обычные кнопки редактора. Модель задаётся настройками LLM бэкенда, перечисленными ниже.

## Фоновый отчёт

В редакторе соедините «Объединение находок» → «AI-отчёт» → Telegram или «Почта». Получатели задаются в ноде уведомления. Воркер сам вызывает модель после сканирования, сохраняет пояснение в истории запуска и передаёт его в текст уведомления. Полный текст доступен на странице результатов и в экспорте Markdown. Состав JSON с находками и решение порога CI определяют сканеры. При ошибке модели нода показывает причину, а уведомление передаёт исходную сводку.

В окружение воркера установите `python -m pip install -r backend/requirements.txt` из корня проекта. Параметры читаются из окружения или корневого `.env` при старте воркера.

| Параметр | Локальная Ollama (по умолчанию) | Внешний API или vLLM |
| --- | --- | --- |
| `LLM_PROVIDER` | `ollama` | `openai_compatible` |
| `LLM_BASE_URL` | `http://127.0.0.1:11434` | Базовый URL провайдера, обычно с `/v1` |
| `LLM_MODEL` | `qwen3.5:4b` | Имя модели у провайдера |
| `LLM_API_KEY` | Пусто | Серверный ключ, если требуется |

Ollama получает запрос к `/api/chat` с JSON-схемой. Совместимый провайдер должен поддерживать `/chat/completions` и `response_format=json_object`. Для удалённого адреса требуется HTTPS. В [Docker Compose](../README.md#деплой-через-docker-compose) внутренний сервис Ollama доступен по `http://ollama:11434` без API-ключа.

В запрос к модели попадают тип правила, название, критичность и число совпадений для каждой из первых шести групп по критичности. Воркер сверяет ответ со схемой и номерами групп, отклоняет распознанные ссылки в тексте модели и подставляет пример файла, строку и advisory из находки. При большем числе групп отчёт отмечает остаток. Формальная проверка ссылок оставляет оценку качества самих советов за разработчиком.

## Инструменты MCP

MCP-клиент запускает `backend.app.mcp_server` как дочерний процесс и общается с ним по stdio. При облачном инференсе клиент может передавать провайдеру возвращённые названия проектов, пути и правила. Результаты MCP следует рассматривать как данные для проверки разработчиком.

| Инструмент | Что получает ассистент |
| --- | --- |
| `node_catalog` | Типы нод, порты, схемы конфигурации из каталога бэкенда |
| `check_workflow` | Результат проверки чернового графа валидатором воркера |
| `prepare_workflow_draft` | Проверенный граф в поле `graph` для импорта в редактор |
| `list_runs` | Запуски пространства токена с ID, статусом и названиями проекта и сценария |
| `run_summary(run_id)` | Статус запуска, покрытие, счётчики и статус AI-отчёта |
| `run_findings(run_id)` | До 50 находок с ID, правилом, критичностью и местом в коде |

Промпт `review_run` помогает выбрать запуск и разобрать находки. Сводки и находки исключают исходники, доказательства, адресатов, реквизиты и текст ответа модели. Для переноса черновика сохраните JSON из `prepare_workflow_draft` в файл, откройте редактор нужного пространства и нажмите «Импорт JSON». Владелец пространства проверяет граф, репозиторий и расписание, затем явно сохраняет, публикует или запускает сценарий.

1. Примените миграции и установите зависимости командой `python -m pip install -r backend/requirements-mcp.txt` в окружение MCP-сервера.
2. В CyberFlow выберите рабочее пространство, откройте «Профиль → Подключения MCP» и выпустите токен. Скопируйте его при выдаче. Токен действует 7 дней и привязан к вашему членству в выбранном пространстве. В этом же разделе можно отозвать токен. Удаление участника отзывает выданные ему токены.
3. В личной конфигурации MCP-клиента замените пути, адрес API и значение переменной `CYBERFLOW_MCP_TOKEN`. Для удалённого API используйте HTTPS. Каталог и проверка графов доступны локально без токена.

```json
{
  "mcpServers": {
    "cyberflow": {
      "command": "C:/projects/Cybergarden2026_cin/.venv/Scripts/python.exe",
      "args": ["-m", "backend.app.mcp_server"],
      "env": {
        "PYTHONPATH": "C:/projects/Cybergarden2026_cin",
        "PYTHONUTF8": "1",
        "CYBERFLOW_API_URL": "http://127.0.0.1:8000/api",
        "CYBERFLOW_MCP_TOKEN": "<токен из Профиль → Подключения MCP>"
      }
    }
  }
}
```

Токен передаётся как `Authorization: Bearer …` только в read-only API `/api/mcp/runs`, `/api/mcp/runs/{run_id}/summary` и `/api/mcp/runs/{run_id}/findings`. Браузерная сессия используется для выпуска и отзыва токенов, а также для импорта в редакторе.
